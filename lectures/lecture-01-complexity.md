# Лекция 1. Введение и алгоритмическая сложность

Дисциплина «Структуры и алгоритмы обработки данных», семестр 1, раздел 1. Темы: понятие алгоритма и модель вычислений, асимптотические нотации O/Ω/Θ, худший, средний и лучший случаи, правила анализа кода, рекуррентные соотношения и мастер-теорема.

## 1. Что такое алгоритм

**Определение.** Алгоритм — конечная последовательность точно определённых, выполнимых действий, преобразующая допустимые входные данные в искомый результат за конечное число шагов.

Четыре классических свойства, отличающих алгоритм от произвольной инструкции:

- **Корректность** — для любого допустимого входа алгоритм завершается и выдаёт результат, удовлетворяющий постановке задачи. «Программа, которая сортирует почти все массивы», алгоритмом сортировки не является.
- **Конечность** — выполнение завершается за конечное число шагов. Бесконечный цикл без выхода — процесс, но не алгоритм.
- **Массовость** — алгоритм решает класс однотипных задач с различными входными данными, а не один конкретный пример.
- **Детерминированность** — каждый шаг определён однозначно: повторный запуск на тех же данных даёт тот же результат тем же путём. Рандомизированные алгоритмы (например, QuickSort со случайным опорным элементом) детерминированы при фиксированном seed — именно поэтому в курсе данные генерируются из seed варианта.

## 2. Зачем анализировать эффективность

Задача: найти число в отсортированном массиве из 10⁹ элементов. Линейный поиск выполняет в худшем случае 10⁹ сравнений — порядка секунды процессорного времени; бинарный поиск — около 30 сравнений (log₂ 10⁹ ≈ 30), результат мгновенный.

Разница — не в железе и не в языке, а в алгоритме: Θ(n) против Θ(log n) — выигрыш в десятки миллионов раз при n = 10⁹. Ускорение компьютера в k раз лишь сдвигает границу применимости медленного алгоритма (для Θ(n²) — в √k раз) и почти не помогает при Θ(2ⁿ). Курс — о том, как видеть эту разницу заранее, до запуска кода.

## 3. Модель вычислений RAM

Анализ ведётся в модели RAM (random access machine): память с произвольным доступом, команды выполняются последовательно, **элементарные операции** — присваивание, арифметика, сравнение, доступ по индексу — стоят O(1) каждая.

**Определение.** Временная сложность алгоритма — функция T(n), равная числу элементарных операций, которые алгоритм выполняет на входе размера n (по умолчанию — в худшем случае).

Аппаратные детали (кэш, частота, компилятор) при этом абстрагируются: они меняют константу, но не порядок роста. Порядок роста — свойство алгоритма; константа — свойство машины. Память оценивается аналогично: сколько дополнительных ячеек требует алгоритм сверх входа.

## 4. Скорость роста функций

Сравним порядки роста при n = 10⁶ и стоимости операции 1 нс:

| Рост | Операций | Время |
| --- | --- | --- |
| log₂ n | ≈ 20 | 20 нс |
| n | 10⁶ | 1 мс |
| n · log₂ n | ≈ 2·10⁷ | 20 мс |
| n² | 10¹² | ≈ 17 минут |
| 2ⁿ | 10³⁰¹⁰³⁰ | дольше жизни Вселенной |

Квадратичный алгоритм уже ощутимо медленный, а экспоненциальный практически неприменим. Граница между «работает» и «не работает» проходит по порядку роста.

## 5. Асимптотические нотации

**Определение (O).** f(n) = O(g(n)) ⇔ существуют c > 0 и n₀ такие, что f(n) ≤ c·g(n) при всех n ≥ n₀. Словами: начиная с некоторого места f растёт не быстрее g с точностью до константы.

**Пример с константами.** 3n² + 10n + 7 = O(n²): при n ≥ 11 верно 10n + 7 ≤ n², значит 3n² + 10n + 7 ≤ 4n² — годятся c = 4, n₀ = 11. Заметьте: формально верно и 3n² = O(n³) — верхняя граница не обязана быть точной.

**Определение (Ω).** f(n) = Ω(g(n)) ⇔ ∃ c > 0, n₀: f(n) ≥ c·g(n) при n ≥ n₀ — нижняя граница, «растёт не медленнее».

**Определение (Θ).** f(n) = Θ(g(n)) ⇔ f = O(g) и f = Ω(g) одновременно — точный порядок роста.

Мнемоника: O — «не хуже, чем g», Ω — «не лучше, чем g», Θ — «ровно порядка g».

Два важных замечания:

1. **«O означает худший случай» — миф.** Нотация описывает рост функции; какой случай оценивать (худший, средний, лучший) — отдельный выбор. Фраза «среднее время QuickSort — Θ(n log n)» — это Θ-оценка именно среднего случая.
2. **Основание логарифма в асимптотике не важно:** log_a n и log_b n различаются константным множителем, поэтому пишут просто O(log n).

## 6. Лучший, средний и худший случаи

**Определения.** Худший случай — максимум T(n) по всем входам размера n; лучший — минимум; средний — математическое ожидание T(n) при заданном распределении входов.

Пример — линейный поиск ключа в массиве из n элементов:

| Случай | Когда | Сравнений |
| --- | --- | --- |
| Лучший | ключ — первый элемент массива | 1 |
| Средний | ключ с равной вероятностью в любой позиции | (n+1)/2 = Θ(n) |
| Худший | ключ — последний элемент или отсутствует | n |

Среднее считается как (1 + 2 + … + n)/n = (n+1)/2. По умолчанию алгоритмы оценивают по худшему случаю — это гарантия при любых данных; оценка среднего требует договорённости о том, какие входы считать равновероятными.

## 7. Правила анализа кода

- **Последовательные блоки** — суммируем и берём старший член: O(n) + O(n²) = O(n²).
- **Вложенные циклы** — перемножаем: n итераций × n итераций = O(n²).
- **Константы и младшие члены** отбрасываем: 3n² + 10n + 7 = Θ(n²).
- **Ветвление** — берём худшую из ветвей.

Итоговая оценка определяется самым «дорогим» участком кода — он и есть узкое место алгоритма.

### Разбор 1. Сумма элементов массива — Θ(n)

```python
def array_sum(a):
    s = 0            # O(1)
    for x in a:      # n итераций
        s += x       # O(1)
    return s         # O(1)
```

Один проход, константная работа на итерации: T(n) = c₁ + c₂·n = Θ(n). Лучший, средний и худший случаи совпадают: массив всегда просматривается целиком, поэтому оценка верна и сверху, и снизу — отсюда Θ.

### Разбор 2. Подсчёт пар равных элементов — Θ(n²)

```python
def count_equal_pairs(a):
    k = 0
    n = len(a)
    for i in range(n):
        for j in range(i + 1, n):
            if a[i] == a[j]:
                k += 1
    return k
```

Число сравнений — сумма арифметической прогрессии (n−1) + (n−2) + … + 1 = n(n−1)/2 = Θ(n²). Следствие: при удвоении размера входа время растёт вчетверо. Забегая вперёд: с хеш-таблицей та же задача решается за Θ(n) — увидим в разделе 4.

### Разбор 3. Бинарное возведение в степень — Θ(log n)

```python
def binary_pow(x, n):
    r = 1
    while n > 0:
        if n % 2 == 1:
            r *= x
        x *= x
        n //= 2
    return r
```

На каждой итерации n уменьшается вдвое, поэтому итераций ⌊log₂ n⌋ + 1. Корректность следует из инварианта цикла: перед каждой итерацией r·xⁿ равно исходному x₀^n₀. Каждая итерация — одно возведение в квадрат, каждый установленный бит n — одно умножение на накопитель: x¹⁰⁰⁰ вычисляется не за 1000 умножений, а примерно за 16 (1000 = 1111101000₂).

## 8. Рекуррентные соотношения

**Определение.** Рекуррентное соотношение — уравнение, выражающее T(n) через значения T на меньших размерах входа, вместе с базовым случаем (обычно T(1) = Θ(1)).

Такие уравнения естественно возникают у рекурсивных алгоритмов: время на входе n складывается из времени рекурсивных вызовов и стоимости нерекурсивной части.

- Бинарный поиск: T(n) = T(n/2) + O(1) — одна половина плюс сравнение.
- Сортировка слиянием: T(n) = 2T(n/2) + O(n) — две половины плюс слияние.

Чтобы получить явную асимптотику, соотношение надо решить. Три инструмента: **метод подстановки** (угадать ответ и доказать индукцией), **дерево рекурсии** (просуммировать стоимость по уровням) и **мастер-теорема** (готовый ответ для стандартной формы).

### Дерево рекурсии для T(n) = 2T(n/2) + n

Раскладываем вызовы в дерево, записывая в узле стоимость нерекурсивной части: корень стоит n; два поддерева по n/2 — уровень в сумме снова n; четыре узла по n/4 — снова n. Уровней log₂ n + 1, каждый стоит n, итого ≈ n·log₂ n = Θ(n log n).

Дерево рекурсии даёт верную гипотезу; строгим доказательством служит метод подстановки (индукция по n).

## 9. Мастер-теорема

**Формулировка.** Пусть T(n) = a·T(n/b) + f(n), где a ≥ 1, b > 1 (a ветвей рекурсии, вход уменьшается в b раз, f(n) — стоимость нерекурсивной части). Обозначим «вес рекурсии» n^(log_b a) и сравним с ним f(n) (ε > 0):

| Случай | Условие | Ответ |
| --- | --- | --- |
| 1 | f(n) = O(n^(log_b a − ε)) — полиномиально медленнее | Θ(n^(log_b a)) |
| 2 | f(n) = Θ(n^(log_b a)) | Θ(n^(log_b a) · log n) |
| 3 | f(n) = Ω(n^(log_b a + ε)) и a·f(n/b) ≤ c·f(n) при c < 1 (условие регулярности) | Θ(f(n)) |

Интуиция: теорема сравнивает, кто «тяжелее» — листья дерева рекурсии (их порядка n^(log_b a)) или корень (f(n)); во втором случае все уровни равнозначны, отсюда множитель log n. Для «обычных» f вроде полиномов условие регулярности выполняется автоматически.

**Примеры.**

| Соотношение | a, b, вес | Случай | Ответ |
| --- | --- | --- | --- |
| T(n) = T(n/2) + O(1) | a=1, b=2 → n⁰ = 1 | 2 | Θ(log n) |
| T(n) = 2T(n/2) + n | a=2, b=2 → n¹ | 2 | Θ(n·log n) |
| T(n) = 4T(n/2) + n | a=4, b=2 → n² | 1 | Θ(n²) |

Мастер-теорема применима не всегда: если f(n) попадает «между» случаями (например, f(n) = n·log n при весе n¹ — зазор не полиномиальный), выручают дерево рекурсии и метод подстановки.

## 10. Теория и эксперимент

Асимптотику можно проверить замерами. Если t = c·nᵏ, то log t = k·log n + log c — в log-log осях степенная зависимость превращается в прямую, наклон которой равен степени k: O(n) даёт наклон 1, O(n²) — наклон 2, O(n log n) — почти прямую с наклоном чуть больше 1.

Методика честных замеров (подробно — [`docs/reproducibility.md`](../docs/reproducibility.md)): прогрев (первый запуск не учитывается), не менее 5 повторов на точку, берётся медиана; ряд размеров с геометрическим шагом; расхождения теории и замеров объясняются (константы, кэш, особенности данных), а не замалчиваются.

Именно это предстоит проделать в [лабораторной работе № 1](../M1-intro-and-basic-structures/kim-01-complexity-analysis.md): реализовать четыре алгоритма из разборов, вывести оценки аналитически, подтвердить их замерами и log-log графиками и выполнить верификацию по методике курса ([`docs/ai-verification.md`](../docs/ai-verification.md)).

## Вопросы для самопроверки

1. Чем Θ отличается от O?
2. Почему «O — это худший случай» — заблуждение?
3. Решите T(n) = 3T(n/3) + n с помощью мастер-теоремы.

<details>
<summary>Ответы</summary>

1. O — только верхняя граница («растёт не быстрее»); Θ — точный порядок: одновременно O и Ω. Из f = Θ(g) следует f = O(g), но не наоборот.
2. Нотация описывает рост функции, а не выбор входа. Худший, средний и лучший случаи определяют, *какую* функцию мы оцениваем; записать любую из них можно в любой нотации.
3. a = 3, b = 3, вес рекурсии n^(log₃ 3) = n¹; f(n) = n = Θ(n¹) — случай 2, ответ Θ(n·log n).

</details>
