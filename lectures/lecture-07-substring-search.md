# Лекция 7. Поиск подстрок

Дисциплина «Структуры и алгоритмы обработки данных», раздел 4. Темы: задача поиска подстроки, наивный поиск и его худший случай, префикс-функция и алгоритм Кнута–Морриса–Пратта (КМП), алгоритм Рабина–Карпа, скользящий хеш и коллизии, алгоритм Бойера–Мура с эвристиками плохого символа и хорошего суффикса, влияние алфавита и длины шаблона, выбор алгоритма по данным.

## 1. Задача поиска подстроки

В [Лекции 6](lecture-06-search-linear-structures.md) ключ искали в массиве: линейный поиск за Θ(n), бинарный поиск в упорядоченном массиве за O(log n). Теперь ключом служит строка, то есть массив символов, и сравнение двух строк длины m требует до m сравнений символов.

**Определение.** Шаблон P длины m входит в текст T длины n со сдвигом s, если T[s + j] = P[j] для всех j от 0 до m − 1. Задача поиска подстроки — найти все сдвиги, с которыми шаблон входит в текст.

Допустимых сдвигов n − m + 1: от 0 до n − m. Вхождения могут перекрываться, и найти нужно все. Сквозной пример лекции: T = aabaabaaabaaab, n = 14; P = aabaaab, m = 7. Шаблон входит в текст со сдвигами 3 и 7, а общие символы двух вхождений — T[7..9].

Алфавит Σ — множество возможных символов, σ — его размер: 2 для битов, 4 для ДНК, 256 для байтов, больше миллиона кодов в Юникоде. Цена поиска измеряется числом сравнений символов; обычно n намного больше m. Задача возникает при поиске в редакторе и в утилите grep, при поиске сигнатур в журналах событий и сетевом трафике, при поиске участков ДНК и при проверке заимствований.

Функции лекции возвращают список сдвигов по возрастанию и рассчитаны на непустой шаблон.

## 2. Наивный поиск

```python
def naive_search(text, pattern):
    n, m = len(text), len(pattern)
    occ = []
    for s in range(n - m + 1):
        j = 0
        while j < m and text[s + j] == pattern[j]:
            j += 1
        if j == m:          # совпали все m
            occ.append(s)
    return occ
```

На каждом сдвиге шаблон сравнивается с окном текста слева направо до первого несовпадения. Сдвигов n − m + 1, на каждом выполняется не больше m сравнений, поэтому время работы O((n − m + 1)·m), а дополнительная память O(1).

В сквозном примере восемь сдвигов, от 0 до 7. Число сравнений по сдвигам: 6, 2, 1, 7, 2, 1, 3, 7, всего 29 сравнений на 14 символов текста. На сдвигах 3 и 7 совпали все семь символов. После каждого сдвига сравнение начинается заново, хотя часть символов окна уже была прочитана.

Худший случай даёт текст aaa…a с шаблоном aa…ab: на каждом сдвиге m − 1 совпадений и несовпадение на последнем символе, всего (n − m + 1)·m сравнений. В типичном тексте несовпадение чаще всего случается на первом же символе окна. Если символы случайного текста над алфавитом из σ символов независимы, то j-е сравнение на сдвиге выполняется, только когда совпали предыдущие j − 1 символов, то есть с вероятностью (1/σ)^(j−1). В сумме получается меньше 1 + 1/σ + 1/σ² + … = σ/(σ − 1) сравнений на сдвиг: 2 при σ = 2 и 1,04 при σ = 26.

При n = 10⁵ худший вход aⁿ и a^(m−1)b с m = 64 требует 6 395 968 сравнений, по 64,0 на символ текста. На текстах заготовки ЛР 7 при m = 16 получается 2,00 сравнения на символ над алфавитом {a, b} и 1,10 на естественно-подобном тексте. Замер на Python (порядок величин): худший вход занимает 0,40 с, типичный текст — около 9,4 мс. Наивный поиск неэффективен на малом алфавите и на данных с повторами: биты, ДНК, журналы с одинаковыми строками. Гарантии линейного времени у него нет.

## 3. Идея алгоритма КМП

На сдвиге 0 сквозного примера пять символов шаблона совпали, на шестом произошло несовпадение. После пяти совпадений участок T[0..4] известен без чтения: это aabaa, префикс шаблона. Наивный поиск сдвигается на 1 и сравнивает эти символы заново.

Сдвиги 1 и 2 заведомо не подходят: под символом T[2] = b в обоих случаях оказывается символ a шаблона. Сдвиг 3 возможен: первые два символа шаблона aa совпадают с уже прочитанными символами текста T[3] и T[4], и сравнение можно продолжить с T[5] и P[2]. Сдвиг на 3 совмещает префикс aa шаблона с суффиксом aa совпавшей части; его величина зависит только от шаблона.

Вывод: для каждого числа совпавших символов нужно знать длину наибольшего префикса совпавшей части, равного её суффиксу. Эти длины образуют префикс-функцию шаблона.

## 4. Префикс-функция

**Определение.** Префикс-функция строки P — массив π длины m: π[i] равно длине наибольшего собственного префикса строки P[0..i], который совпадает с её суффиксом.

Префикс строки — её начало, суффикс — её конец; собственный префикс короче самой строки, поэтому π[0] = 0. Для шаблона aabaaab:

| i | P[0..i] | Префикс, равный суффиксу | π[i] |
| --- | --- | --- | --- |
| 0 | a | — | 0 |
| 1 | aa | a | 1 |
| 2 | aab | — | 0 |
| 3 | aaba | a | 1 |
| 4 | aabaa | aa | 2 |
| 5 | aabaaa | aa | 2 |
| 6 | aabaaab | aab | 3 |

У строки aabaa префикс aa равен суффиксу aa, более длинных совпадений нет, поэтому π[4] = 2. За шаг значение растёт не больше чем на 1: π[i + 1] ≤ π[i] + 1. Смысл для поиска такой: если шаблон совпал с текстом на i + 1 символах, то π[i] из них останутся совпавшими после сдвига. Второй пример, из самопроверки ЛР 7: π(abcabcd) = [0, 0, 0, 1, 2, 3, 0].

Префикс-функция зависит только от шаблона. Её вычисляют один раз, до чтения текста.

```python
def prefix_function(pattern):
    m = len(pattern)
    pi = [0] * m
    k = 0                 # совпало символов
    for i in range(1, m):
        while k > 0 and pattern[i] != pattern[k]:
            k = pi[k - 1]     # короче
        if pattern[i] == pattern[k]:
            k += 1
        pi[i] = k
    return pi
```

Перед шагом i переменная k равна π[i − 1]: префикс длины k равен суффиксу строки P[0..i − 1]. Если P[i] = P[k], совпадение продлевается, и π[i] = k + 1. Иначе берётся следующий по длине префикс, равный суффиксу; его длина равна π[k − 1]. Пример: при i = 5 и k = 2 префикс aa в позициях 0–1 равен суффиксу aa в позициях 3–4, но P[5] ≠ P[2], поэтому k = π[1] = 1. Теперь P[5] = P[1], и π[5] = 2.

Время построения O(m): k увеличивается не больше m − 1 раз и каждый раз на 1, а каждый переход `k = pi[k - 1]` его уменьшает, поэтому переходов не больше, чем увеличений. Это амортизированная оценка в смысле [лекции 2](lecture-02-recursion-linear-structures.md): оценивается сумма по всей серии шагов, а не каждый шаг отдельно.

### Разбор 1. Префикс-функция шаблона aabaaab по шагам

π[0] = 0. В столбце «k до шага» записано значение π[i − 1].

| i | P[i] | k до шага | Сравнения и переходы | π[i] |
| --- | --- | --- | --- | --- |
| 1 | a | 0 | P[1] = P[0], k = 1 | 1 |
| 2 | b | 1 | P[2] ≠ P[1], k = π[0] = 0; P[2] ≠ P[0], k = 0 | 0 |
| 3 | a | 0 | P[3] = P[0], k = 1 | 1 |
| 4 | a | 1 | P[4] = P[1], k = 2 | 2 |
| 5 | a | 2 | P[5] ≠ P[2], k = π[1] = 1; P[5] = P[1], k = 2 | 2 |
| 6 | b | 2 | P[6] = P[2], k = 3 | 3 |

Всего выполнено 8 сравнений символов при верхней границе 2m − 3 = 11. Переходы по π есть только на шагах 2 и 5. На шаге 5 после перехода осталось k = 1: префикс a равен суффиксу a строки aabaa. Крайние случаи: π(aaaaaa) = [0, 1, 2, 3, 4, 5] и π(abcdef) = [0, 0, 0, 0, 0, 0], в обоих по 5 сравнений.

## 5. Алгоритм Кнута–Морриса–Пратта

Алгоритм опубликовали Д. Кнут, Дж. Моррис и В. Пратт в 1977 году.

```python
def kmp_search(text, pattern):
    m = len(pattern)
    pi = prefix_function(pattern)
    occ, k = [], 0        # k — совпало символов
    for i in range(len(text)):
        while k > 0 and text[i] != pattern[k]:
            k = pi[k - 1]     # сдвиг шаблона
        if text[i] == pattern[k]:
            k += 1
        if k == m:            # вхождение
            occ.append(i - m + 1)
            k = pi[k - 1]
    return occ
```

Цикл тот же, что в префикс-функции, но символ берётся из текста. Переменная k хранит длину наибольшего префикса шаблона, которым заканчивается прочитанный текст T[0..i]. При несовпадении выполняется переход k = π[k − 1]: шаблон сдвигается вправо на k − π[k − 1], а индекс i остаётся на месте. Равенство k = m означает вхождение со сдвигом i − m + 1. После него выполняется k = π[m − 1], поэтому перекрывающиеся вхождения не теряются.

Индекс i только растёт: текст читается один раз слева направо. Поэтому КМП может искать в потоке данных, не храня прочитанное.

В сквозном примере на сдвиге 0 пять символов совпадают, на шестом символе шаблона происходит несовпадение, и k становится равным π[4] = 2. На сдвиге 3 первые два символа шаблона не сравниваются: о совпадении известно из префикс-функции. Остальные пять совпадают, это вхождение, и k = π[6] = 3: суффикс aab служит началом следующего вхождения, которое находится на сдвиге 7 после четырёх сравнений. Сдвиги 1, 2, 4, 5 и 6 пропущены без единого сравнения. Всего 15 сравнений: 14 символов текста и одно повторное, с символом T[5]; у наивного поиска 29.

## 6. Оценка времени КМП

После каждого сравнения либо i увеличивается на 1, либо шаблон сдвигается вправо переходом по π. Индекс i увеличивается ровно n раз. Переход по π уменьшает k, а увеличивается k только вместе с i и только на 1, поэтому переходов не больше n. Итог: не больше 2n сравнений при поиске и 2m при построении π. Время Θ(n + m), память Θ(m).

| Вход, n = 10⁵ | Наивный поиск, сравнений | КМП, сравнений |
| --- | --- | --- |
| aⁿ и a^(m−1)b, m = 64 | 6 395 968 | 199 937 |
| алфавит {a, b}, m = 16 | 199 583 | 136 404 |
| естественно-подобный текст, m = 16 | 110 193 | 102 078 |

Худший вход наивного поиска стоит КМП меньше 2n сравнений; замер на Python (порядок величин): 11 мс против 0,40 с. На типичном тексте выигрыш мал: оба алгоритма делают около n сравнений. Преимущества КМП: гарантия линейного времени и работа с потоком данных.

T = aabaabaaabaaab, P = aabaaab, π = [0, 1, 0, 1, 2, 2, 3].

| № | i | T[i] | k | P[k] | Результат |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | a | 0 | a | совпали, k = 1 |
| 2 | 1 | a | 1 | a | совпали, k = 2 |
| 3 | 2 | b | 2 | b | совпали, k = 3 |
| 4 | 3 | a | 3 | a | совпали, k = 4 |
| 5 | 4 | a | 4 | a | совпали, k = 5 |
| 6 | 5 | b | 5 | a | не совпали, k = π[4] = 2 |
| 7 | 5 | b | 2 | b | совпали, k = 3 |
| 8 | 6 | a | 3 | a | совпали, k = 4 |
| 9 | 7 | a | 4 | a | совпали, k = 5 |
| 10 | 8 | a | 5 | a | совпали, k = 6 |
| 11 | 9 | b | 6 | b | вхождение 3, k = π[6] = 3 |
| 12 | 10 | a | 3 | a | совпали, k = 4 |
| 13 | 11 | a | 4 | a | совпали, k = 5 |
| 14 | 12 | a | 5 | a | совпали, k = 6 |
| 15 | 13 | b | 6 | b | вхождение 7, k = π[6] = 3 |

Единственное несовпадение — сравнение 6; символ T[5] сравнивается дважды, остальные по одному разу. Индекс i не уменьшается.

Точная оценка: величина 2i − k перед первым сравнением равна 0 и никогда не превосходит 2n. Каждое сравнение её увеличивает:

| Исход сравнения | i | k | 2i − k |
| --- | --- | --- | --- |
| символы совпали | +1 | +1 | +1 |
| не совпали, k > 0 | 0 | уменьшается | не меньше +1 |
| не совпали, k = 0 | +1 | 0 | +2 |

Значит, сравнений не больше 2n. Переход k = π[m − 1] после вхождения сравнением не является, а величину 2i − k он только увеличивает.

Худший вход для КМП тот же, что для наивного поиска: aⁿ и a^(m−1)b. Первые m − 1 символов текста требуют по одному сравнению. Дальше на каждый символ приходится два: несовпадение с b, переход по π и совпадение с a. Всего 2n − m + 1 сравнений: 36 при n = 20 и m = 5 (у наивного поиска 80), 199 937 при n = 100 000 и m = 64.

## 7. Алгоритм Рабина–Карпа

Алгоритм Р. Карпа и М. Рабина (1987) сравнивает не строки, а числа.

**Определение.** Полиномиальный хеш строки s длины m по основанию b и модулю q: h(s) = (s[0]·b^(m−1) + s[1]·b^(m−2) + … + s[m − 1]) mod q, где s[j] — код символа.

Строка читается как число в системе счисления с основанием b; хеш равен остатку от деления этого числа на q. У равных строк хеши равны, у разных почти всегда различаются. Два числа сравниваются за O(1), две строки — за O(m). Алгоритм состоит из четырёх шагов:

1. вычислить хеш шаблона и хеш первого окна T[0..m − 1] за O(m);
2. на каждом сдвиге сравнить хеш окна с хешем шаблона;
3. если хеши равны, сравнить окно с шаблоном посимвольно;
4. хеш следующего окна получить из текущего за O(1).

В сквозном примере P = aabaaab. Параметры взяты как в ЛР 7: b = 256, q = 1 000 000 007 (простое число), код символа — `ord(c)`. Хеш шаблона h(P) = 717 523 757.

| Сдвиг | Окно | Хеш окна | Сравнение с h(P) |
| --- | --- | --- | --- |
| 0 | aabaaba | 717 524 012 | не равен |
| 1 | abaabaa | 934 242 107 | не равен |
| 2 | baabaaa | 414 074 035 | не равен |
| 3 | aabaaab | 717 523 757 | равен: посимвольная проверка |

Хеш следующего окна вычисляется из хеша текущего: нужно убрать вклад левого символа, умножить на b и прибавить правый символ.

```
h′ = ((h − T[s]·b^(m−1))·b + T[s+m]) mod q
```

Пример на цифрах: строка 314159 по основанию 10, окно 314 на сдвиге 0 и окно 141 на сдвиге 1. Из 314 вычитается 3·100, результат умножается на 10 и прибавляется 1: (314 − 3·100)·10 + 1 = 141. Степень b^(m−1) mod q вычисляется один раз. В Python остаток от деления неотрицателен; в C и Java после вычитания прибавляют q.

```python
def rabin_karp_search(text, pattern, B=256, Q=10**9 + 7):
    n, m = len(text), len(pattern)
    if m == 0 or m > n:           # окон нет
        return []
    high = pow(B, m - 1, Q)       # b^(m-1) mod q
    hp = ht = 0
    for j in range(m):            # шаблон и первое окно
        hp = (hp * B + ord(pattern[j])) % Q
        ht = (ht * B + ord(text[j])) % Q
    occ = []
    for s in range(n - m + 1):
        if hp == ht and text[s:s + m] == pattern:
            occ.append(s)
        if s < n - m:             # следующее окно
            ht = ((ht - ord(text[s]) * high) * B
                  + ord(text[s + m])) % Q
    return occ
```

В заготовке ЛР 7 параметры называются `base` и `mod`, а проверка окна выполняется циклом со счётчиком сравнений.

## 8. Коллизии и посимвольная проверка

**Определение.** Коллизия — равенство хешей разных строк. Хешей всего q, а строк длины m — σᵐ: при σᵐ > q коллизии неизбежны.

Хешей q = 10⁹ + 7, а строк из четырёх байтов 256⁴ = 4 294 967 296, поэтому коллизии есть уже среди строк длины 4. Для двух случайных строк вероятность равных хешей около 1/q. По парадоксу дней рождения среди 37 000 случайных строк коллизия есть с вероятностью около 1/2.

Пример: строки joaxiq и csyfax имеют один хеш 608 376 195 (пара найдена перебором 16 487 случайных строк). Поиск joaxiq в тексте «log csyfax end» без проверки возвращает сдвиг 4, то есть вхождение, которого нет. Отсутствие проверки является дефектом реализации. При равенстве хешей окно сравнивается с шаблоном посимвольно, это до m сравнений. Ложное совпадение стоит времени, но не даёт ошибки. В ЛР 7 проверка обязательна.

Ожидаемое число ложных совпадений равно (n − m + 1)/q. Измерение на текстах ЛР 7 при m = 16 (99 985 окон):

| Модуль q | Ожидание | Текст над {a, b} | Естественно-подобный текст |
| --- | --- | --- | --- |
| 101 | 990 | 952 | 996 |
| 1 009 | 99 | 128 | 101 |
| 10⁹ + 7 | 0,0001 | 0 | 0 |

При большом модуле среднее время работы O(n + m). Худший случай — O(nm): много настоящих вхождений или специально подобранные коллизии. Посимвольная проверка при равенстве хешей нужна всегда, а случайное основание или два хеша по разным модулям защищают от специально подобранных входов. На малом модуле дефект хорошо заметен: на тексте над {a, b} при m = 16 и q = 101 поиск без проверки возвращает 959 «вхождений» вместо 7.

## 9. Алгоритм Бойера–Мура

Алгоритм Р. Бойера и Дж. Мура (1977) сдвигает шаблон по тексту слева направо, а символы сравнивает справа налево, начиная с последнего символа шаблона.

Пример: текст «in the log: login failed» (n = 24), шаблон login (m = 5). На сдвиге 0 последний символ окна h не совпал с n. Символа h в шаблоне нет: ни один сдвиг, накрывающий h, не даст вхождения, и шаблон сдвигается сразу на m = 5. На сдвиге 5 символ g не совпал с n; символ g стоит в шаблоне на позиции 2, и сдвиг на 4 − 2 = 2 ставит его под g текста. Вхождение найдено на сдвиге 12, остальные окна отбрасываются одним сравнением (разбор 4). Всего выполнено 10 сравнений на 24 символа текста; у наивного поиска 27, у КМП 26. Часть текста не прочитана вовсе.

**Определение.** Плохой символ — символ текста c = T[s + j], на котором сравнение справа налево дало несовпадение.

Для сдвига нужна таблица позиций последнего вхождения каждого символа шаблона. Она хранится в словаре: в Юникоде больше миллиона кодов.

```python
def bad_char_table(pattern):
    return {c: i for i, c
            in enumerate(pattern)}
# login: l→0, o→1, g→2, i→3, n→4
```

```python
def boyer_moore_search(text, pattern):
    n, m = len(text), len(pattern)
    last = bad_char_table(pattern)
    occ, s = [], 0
    while s <= n - m:
        j = m - 1
        while j >= 0 and text[s + j] == pattern[j]:
            j -= 1
        if j < 0:              # вхождение
            occ.append(s)
            s += 1
        else:                  # плохой символ
            c = text[s + j]
            s += max(1, j - last.get(c, -1))
    return occ
```

Эвристика плохого символа различает три случая:

1. символа c в шаблоне нет — сдвиг на j + 1;
2. последнее вхождение c находится левее j — сдвиг на j − last[c];
3. последнее вхождение c находится правее j — сдвиг на 1.

После вхождения шаблон сдвигается на 1, поэтому перекрывающиеся вхождения не теряются.

### Разбор 4. Бойер–Мур по шагам

Текст «in the log: login failed», шаблон login; таблица: l→0, o→1, g→2, i→3, n→4. Точкой в окнах показан пробел. Во всех окнах, кроме вхождения, несовпадение происходит при j = 4.

| Сдвиг | Окно | Сравнений | Плохой символ | Правило | Шаг |
| --- | --- | --- | --- | --- | --- |
| 0 | in·th | 1 | h | нет в шаблоне: 4 + 1 = 5 | 5 |
| 5 | e·log | 1 | g | last = 2: 4 − 2 = 2 | 2 |
| 7 | log:· | 1 | пробел | нет в шаблоне: 4 + 1 = 5 | 5 |
| 12 | login | 5 | — | вхождение | 1 |
| 13 | ogin· | 1 | пробел | нет в шаблоне: 4 + 1 = 5 | 5 |
| 18 | faile | 1 | e | нет в шаблоне: 4 + 1 = 5 | 5 |

Всего 10 сравнений. После сдвига 18 следующий сдвиг 23 больше n − m = 19, и поиск окончен. Третье правило иллюстрирует окно nogin с шаблоном login: совпали символы ogin, плохой символ n обнаружен при j = 0, а last[n] = 4. Разность 0 − 4 меньше 1, поэтому шаблон сдвигается на 1.

## 10. Оценки Бойера–Мура и эвристика хорошего суффикса

Лучший случай — n/m сравнений: читается каждый m-й символ текста. Чем длиннее шаблон, тем быстрее поиск. Худший случай с одной эвристикой плохого символа — Θ(nm). На входе aⁿ и ba^(m−1) плохой символ a стоит в шаблоне правее места несовпадения, и сдвиг всегда равен 1.

Вторая эвристика использует совпавшую часть окна. Совпавший суффикс шаблона известен без чтения текста, как совпавший префикс в КМП. Шаблон сдвигается до следующего места, где он согласуется с этим суффиксом. Пример: текст из десяти символов a, шаблон baaaa. На сдвиге 0 четыре символа a совпали справа налево, несовпадение произошло на первом символе шаблона b. Эвристика плохого символа даёт сдвиг на 1. Эвристика хорошего суффикса даёт сдвиг на 5: суффикс aaaa больше нигде в шаблоне не встречается. Таблица сдвигов строится по шаблону за O(m); из двух сдвигов берётся больший.

Правило точнее: шаблон сдвигается до ближайшего места, где он согласуется с совпавшим суффиксом и где перед этим суффиксом стоит другой символ; если такого места нет, под конец суффикса встаёт начало шаблона. Таблица для шаблона aabaaab (сдвиг зависит от того, сколько символов совпало справа налево до несовпадения):

| Совпало | Суффикс | Сдвиг | Почему |
| --- | --- | --- | --- |
| 0 | — | 1 | несовпадение на последнем символе: правило не работает |
| 1 | b | 7 | другого b, перед которым не a, в шаблоне нет |
| 2 | ab | 7 | то же: ab встречается ещё раз, но перед ним снова a |
| 3 | aab | 4 | aab — начало шаблона: оно встаёт под совпавший суффикс |
| 4–6 | aaab, … | 4 | начало aab совпадает с концом суффикса |
| 7 | aabaaab | 4 | после вхождения: период шаблона, m − π[m − 1] = 7 − 3 |

В сквозном примере лекции алгоритм с одним плохим символом делает 20 сравнений, с обеими эвристиками — 17.

С обеими эвристиками выполняется не больше 3n сравнений, если вхождений нет (Р. Коул, 1991); при многих вхождениях линейное время даёт правило Галила. В ЛР 7 хороший суффикс является требованием уровня «10». Счётчики на крайних входах при n = 10⁵ и m = 64:

| Вход | Вхождений | Наивный поиск | КМП | Бойер–Мур, плохой символ | Бойер–Мур + хороший суффикс |
| --- | --- | --- | --- | --- | --- |
| aⁿ и a^(m−1)b | 0 | 6 395 968 | 199 937 | 99 937 | 99 937 |
| aⁿ и ba^(m−1) | 0 | 99 937 | 100 000 | 6 395 968 | 99 968 |
| aⁿ и a^m | 99 937 | 6 395 968 | 100 000 | 6 395 968 | 6 395 968 |
| aⁿ и b^m | 0 | 99 937 | 100 000 | 1 562 | 1 562 |

У каждого алгоритма без гарантии свой худший вход: у наивного поиска это шаблон a^(m−1)b, у Бойера–Мура с плохим символом — ba^(m−1). КМП на всех четырёх входах делает от n до 2n сравнений. Шаблон a^m входит в текст 99 937 раз, каждое вхождение проверяется целиком, и хороший суффикс не помогает; Рабин–Карп на этом входе делает столько же сравнений. Замер на Python (порядок величин): наивный поиск на первом входе работает 0,40 с, Бойер–Мур с плохим символом на втором — 0,39 с, с хорошим суффиксом — 6,1 мс.

## 13. Поиск подстроки в стандартной библиотеке

В CPython оператор `in` и методы `str.find`, `str.count`, `str.replace` используют один поиск, написанный на C: упрощённый вариант Бойера–Мура (Хорспула) с компактной таблицей символов. Для длинных шаблонов с Python 3.10 применяется алгоритм Two-Way (М. Крошмор, Д. Перрен): O(n + m) в худшем случае и O(1) дополнительной памяти. Модуль `re` для литерального начала шаблона строит таблицу перекрытий, то есть ту же префикс-функцию. Утилита GNU grep ищет строки вариантом Бойера–Мура.

Замер при n = 10⁵ и m = 64 (порядок величин): на естественно-подобном тексте лучший из алгоритмов лекции, Бойер–Мур, работает 1,1 мс, а `str.find` — 0,02 мс; на входе aⁿ и a^(m−1)b лучший алгоритм, КМП, работает 11 мс, а `str.find` — 0,03 мс. В рабочем коде применяют стандартные средства. Собственная реализация нужна, когда их нет: поиск в потоке, много шаблонов сразу, счётчики операций. В ЛР 7 метод `str.find` служит только эталоном для сверки: функция `reference_occurrences` вызывает его с шагом 1 и находит все вхождения, включая перекрывающиеся.

## 14. Сравнение и выбор алгоритма

| Алгоритм | Подготовка | Поиск, худший случай | Типичный текст | Память |
| --- | --- | --- | --- | --- |
| наивный | — | Θ(nm) | около n сравнений | O(1) |
| КМП | Θ(m) | Θ(n) | от n до 2n сравнений | Θ(m) |
| Рабин–Карп | Θ(m) | Θ(nm) | хеш каждого окна | O(1) |
| Бойер–Мур, плохой символ | Θ(m) | Θ(nm) | меньше n, до n/m | O(m) |
| Бойер–Мур + хороший суффикс | Θ(m) | Θ(nm); 3n без вхождений | меньше n, до n/m | Θ(m) |

Оценки подготовки и памяти приведены для таблицы плохого символа в виде словаря; с массивом на весь алфавит они равны Θ(m + σ). Гарантию линейного времени на любом входе даёт только КМП. Только Бойер–Мур не читает часть символов текста; остальные алгоритмы просматривают текст целиком. Рабин–Карп сравнивает не символы, а числа, и легко обобщается на много шаблонов. Наивный поиск остаётся эталоном для проверки остальных.

Перед выбором алгоритма отвечают на три вопроса: каков размер алфавита, какова длина шаблона, сколько шаблонов и запросов.

| Условия задачи | Алгоритм | Причина |
| --- | --- | --- |
| короткий текст, разовый поиск | стандартная библиотека или наивный | подготовка не окупается |
| малый алфавит, повторы, поток данных | КМП | не больше 2n сравнений, текст читается один раз |
| длинный шаблон, большой алфавит | Бойер–Мур | длинные сдвиги, до n/m сравнений |
| много шаблонов одной длины | Рабин–Карп | хеши шаблонов хранятся в множестве |
| много шаблонов разной длины | Ахо–Корасик | один проход по тексту для всех шаблонов |
| много запросов к одному тексту | индекс: суффиксный массив | O(m log n) на запрос |

Алгоритм Ахо–Корасик обобщает КМП на набор шаблонов. Суффиксный массив — упорядоченный массив суффиксов текста, по которому ищут бинарным поиском из [Лекции 6](lecture-06-search-linear-structures.md).

В [лабораторной работе № 7](../M4-search-and-hashing/kim-07-substring-search.md) нужно реализовать наивный поиск (он служит эталоном для сверки остальных алгоритмов), КМП с отдельной функцией `prefix_function`, алгоритм Рабина–Карпа с полиномиальным хешем и обязательной посимвольной проверкой и алгоритм Бойера–Мура с эвристикой плохого символа; эвристика хорошего суффикса относится к уровню «10» рубрики. Каждая функция возвращает все вхождения, включая перекрывающиеся, и число сравнений символов; для пустого шаблона ответ — пустой список. Алгоритмы сравниваются по числу сравнений и по времени на текстах своего варианта (малый алфавит и естественно-подобный текст, шаблоны нескольких длин), а отчёт о применимости отвечает на три вопроса раздела 14 по собственным замерам. Методика замеров — [`docs/reproducibility.md`](../docs/reproducibility.md).

Верификация ([`docs/ai-verification.md`](../docs/ai-verification.md)): граничные случаи (шаблон равен тексту, шаблон длиннее текста, пустой текст) и сверка всех алгоритмов с наивным поиском и с эталоном на `str.find` на случайных строках над малым алфавитом, где часты перекрытия.

Неверная реализация часто проходит ручные примеры. Типичные дефекты:

- после вхождения в КМП k сбрасывается в 0 вместо π[m − 1], и перекрывающиеся вхождения теряются; дефект обнаруживает поиск aa в тексте aaaa с ответом [0, 1, 2];
- в алгоритме Рабина–Карпа нет посимвольной проверки; при модуле 10⁹ + 7 случайные тесты этого не замечают (раздел 8), поэтому реализацию проверяют и на малом модуле;
- в алгоритме Бойера–Мура сдвиг j − last[c] не ограничен снизу единицей и становится отрицательным, когда плохой символ стоит в шаблоне правее места несовпадения (разбор 4).

В [дополнительном задании № 3](../Cases/kim-03-astra-log-anomalies.md) (кейс ГК «Астра») сигнатуры в журнале событий ОС ищутся алгоритмом из ЛР 7: КМП или Бойером–Муром. Выбор обосновывается длиной сигнатур и алфавитом.

2. Двенадцать. Допустимых сдвигов 6 − 3 + 1 = 4, и на каждом два символа a совпадают, а третье сравнение (a текста с b шаблона) даёт несовпадение: 4·3 = 12. Вхождений нет; это худший случай наивного поиска.
3. На 2. Сравнение начинается с последнего символа шаблона, j = 4: символ g текста не совпадает с n. Последнее вхождение g в шаблоне находится на позиции 2, левее j, поэтому сдвиг равен j − last[g] = 4 − 2 = 2: символ g шаблона встаёт под g текста.
