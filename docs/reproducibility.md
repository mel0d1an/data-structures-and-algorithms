# Настройка окружения и воспроизводимость

## 1. Установка окружения

Требуется Python **3.10+**.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Проверка окружения (секунды, CPU):

```bash
pytest tests/
```

Все тесты должны проходить. Если тест падает — окружение установлено неверно; типовые причины: устаревший Python, отсутствие пакета из `requirements.txt`.

Проверка внутренних ссылок и структуры репозитория (после любых правок документов):

```bash
python scripts/check_links.py            # ссылки, якоря, структура
python scripts/check_links.py --external # + внешние ссылки (требуется интернет)
```

Скрипт проверяет существование файлов и якорей во всех `*.md`, пары `kim-NN`/`rubric-NN`, обязательные разделы КИМ, шкалу рубрик (10/8/6/4/0–3) и согласованность БРС (потолок 100 баллов, порог автомата 70). Та же проверка автоматически выполняется в CI на каждый push и pull request (`.github/workflows/check.yml`).

## 2. Генерация данных

Наборы данных для лабораторных и ДЗ генерируются локально и не коммитятся (см. `.gitignore`):

```bash
python scripts/generate_data.py --variant N          # все наборы для варианта N
python scripts/generate_data.py --variant N --only logs        # журнал событий (ДЗ 3)
python scripts/generate_data.py --variant N --only embeddings  # псевдо-эмбеддинги (ДЗ 4)
```

Файлы попадают в `data/generated/`. Генерация детерминирована: при одном и том же варианте наборы совпадают побайтно.

## 3. Фиксация случайности

Базовый seed курса — `30 + номер варианта`. В начале каждой работы:

```python
VARIANT = ...            # номер варианта (закрепляется на первом занятии)
SEED = 30 + VARIANT
import random
random.seed(SEED)
import numpy as np
np.random.seed(SEED)
```

Замечания:

- фиксируйте seed **один раз в начале** программы, а не перед каждым вызовом;
- данные для замеров генерируйте заранее и переиспользуйте между алгоритмами — сравнение честно только на одинаковых входах.

## 4. Методика бенчмаркинга

Эмпирические замеры — обязательная часть большинства ЛР; чтобы результаты были воспроизводимы и сопоставимы с асимптотикой:

1. **Таймер** — `time.perf_counter()` (или `timeit`); не `time.time()`.
2. **Прогрев** — первый запуск каждой реализации не учитывается (кэши, JIT-эффекты интерпретатора).
3. **Повторы** — каждая точка усредняется не менее чем по 5 запускам; фиксируйте медиану, а не минимум/максимум.
4. **Ряд размеров** — не менее 5–6 значений n с геометрическим шагом (например, 10³, 3·10³, 10⁴, 3·10⁴, 10⁵).
5. **Графики** — log-log; на таком графике O(n) — прямая с наклоном 1, O(n²) — с наклоном 2, O(n log n) — почти прямая с наклоном чуть больше 1.
6. **Условия** — замеры на одной машине, от батареи не измерять, тяжёлые фоновые процессы закрыть; в отчёте указать CPU и версию Python.
7. **Выводы** — сопоставление теоретической оценки и наблюдаемого наклона; расхождения объясняются (константы, кэш-эффекты, особенности данных), а не замалчиваются.
