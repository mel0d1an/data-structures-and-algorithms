# КИМ-03. Дополнительное практическое задание 3 «Обнаружение аномалий в журналах событий ОС» (кейс ГК «Астра»)

## 1. Назначение и формируемые результаты

КИМ построен на кейсе индустриального партнёра ГК «Астра» «Обнаружение аномалий в журналах событий ОС» (кейс адаптирован: используются синтетические данные). Результат: обучающийся собирает из изученных структур и алгоритмов работающий детектор аномалий — частотный анализ на собственной хеш-таблице, поиск всплесков скользящим окном, поиск сигнатур в тексте событий, — оценивает сложность каждого этапа, подтверждает её замерами и количественно верифицирует детектор по эталонной разметке (точность и полнота).

| ОПК-6 | ОПК-6.2 | Критическая проверка собственного программного решения: верификация детектора по файлу-ответу, вычисление и интерпретация точности и полноты |

## 3. Цель работы

Научиться применять хеш-таблицы, метод скользящего окна и алгоритмы поиска подстрок к прикладной задаче обнаружения аномалий в журналах событий ОС и количественно верифицировать построенный детектор.

## 4. Условия проведения

- **Форма:** самостоятельная работа (дополнительное практическое задание), выполняется в часы СР после раздела 4 «Алгоритмы поиска и хеш-таблицы».
- **Срок:** объявляется преподавателем при выдаче задания.
- **Трудоёмкость:** ~6 часов СР.
- **ПО:** Python 3.10+; см. [`resources/software/`](../resources/software/README.md).
- **Вариантность:** seed генератора данных — `30 + номер варианта` (см. [`docs/reproducibility.md`](../docs/reproducibility.md)); тип контролируемого события, порог всплеска и набор сигнатур сообщаются при выдаче задания.

## 6. Задание

1. Сгенерировать журнал своего варианта: `python ../scripts/generate_data.py --variant N --only logs`. Команда создаёт синтетический журнал событий CSV `timestamp;process;event_type;details` с внедрёнными аномалиями, а также файл-ответ с позициями внедрённых аномалий — он используется **только** на шаге 6 для самопроверки, а не при разработке детектора.
2. Подсчитать частоты типов событий по процессам (ключ — пара `(process, event_type)`) **собственной хеш-таблицей из ЛР 8**; корректность подсчёта сверить с `collections.Counter`.
3. Пройти по журналу **скользящим окном по времени (10 с)** и найти окна, в которых частота заданного типа события превышает порог (всплесковые аномалии). Реализовать проход за один просмотр журнала (метод двух указателей), корректность сверить с наивным эталоном на малых данных.
4. Найти заданные сигнатуры (подстроки) в поле `details` **алгоритмом из ЛР 7** — КМП или Бойер–Мур; выбор обосновать аналитически (длины сигнатур, размер алфавита, характер текста), учесть перекрывающиеся вхождения, корректность сверить с наивным поиском на `str.find`.
5. Составить отчёт: перечень найденных аномалий (всплесковые окна и строки с сигнатурами), аналитическая оценка сложности каждого этапа, замеры времени этапов на журналах не менее трёх размеров по методике бенчмаркинга (прогрев, ≥5 повторов, медиана), сопоставление замеров с оценками.
6. Верифицировать детектор по файлу-ответу: вычислить точность (precision) и полноту (recall) обнаружения, проинтерпретировать результат — какие аномалии пропущены или обнаружены ложно и почему.

По решению преподавателя вместо журналов событий задание может выполняться на материале кейса hh.ru «Скоринг подозрительных вакансий»: построение признаков текстов вакансий поиском подстрок (сигнатуры подозрительных формулировок) и хеш-структурами (частоты термов); схема оценивания, вариантность и требования к верификации — те же.

## 7. Формат сдачи

- Код детектора и краткий отчёт (найденные аномалии, оценки сложности, таблицы/графики замеров, точность и полнота с интерпретацией) в личном репозитории обучающегося.
- **Защита:** демонстрация детектора на журнале своего варианта + ответы на вопросы (см. раздел 10).

## 8. Критерии и шкала

Оценивание по 10-балльной рубрике — см. [`rubric-03-astra-log-anomalies.md`](rubric-03-astra-log-anomalies.md). Балл входит в БРС с коэффициентом 0,3 (до 3 баллов за ДЗ 3).

## 9. Правила использования внешних ресурсов и генеративного ИИ

- **Разрешено:** документация Python, справочники; генеративный ИИ — для пояснений материала, отладки собственного кода и генерации дополнительных тестовых данных.
- **Обязательно:** любой использованный ИИ-код верифицируется по методике [`docs/ai-verification.md`](../docs/ai-verification.md) (инварианты, репрезентативные тесты, сравнение с эталоном, оценка сложности); результаты верификации включаются в отчёт.
- **Анти-чит:** детектор строится и отлаживается без обращения к файлу-ответу — файл-ответ применяется только для итоговой верификации; подгонка детектора под файл-ответ (жёсткое кодирование позиций аномалий) приравнивается к невыполнению задания. Замеры выполняются на журнале своего варианта; выводы формулируются по собственным результатам. Непонимание собственного решения на защите = 0 баллов по критериям «полнота верификации» и «обоснованность выводов».

## 10. Вопросы для защиты

1. Почему для подсчёта частот выбрана хеш-таблица и какова амортизированная сложность подсчёта по всему журналу?
2. Какова сложность прохода скользящим окном по журналу и за счёт чего она достигается по сравнению с наивным пересчётом каждого окна?
3. Чем обоснован выбор алгоритма поиска подстрок (КМП или Бойер–Мур) для сигнатур вашего варианта и какова его сложность?
4. Как верифицировался детектор по файлу-ответу и что показали точность и полнота: какие аномалии пропущены или обнаружены ложно и почему?
