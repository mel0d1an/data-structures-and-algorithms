# КИМ-04. Дополнительное практическое задание 4 «Семантический подбор резюме и вакансий по векторным представлениям»

## 1. Назначение и формируемые результаты

КИМ построен на кейсе индустриального партнёра hh.ru «Семантический подбор резюме и вакансий» (адаптация: псевдо-эмбеддинги малой размерности, синтетические данные). Результат: обучающийся реализует точный поиск ближайших соседей по косинусной близости, ускоряет его бакетизацией случайными гиперплоскостями (LSH) на собственной хеш-таблице, измеряет компромисс «скорость — полнота» (время запроса и recall@k) и формулирует обоснованный вывод о применимости подходов, включая обзор промышленных решений. Тема рекомендована для кейс-чемпионата (см. [`Cases/README.md`](README.md)).

## 3. Цель работы

Научиться решать задачу семантического подбора как задачу поиска ближайших соседей в векторном пространстве: реализовать точный поиск, ускорить его приближённой бакетизацией и количественно оценить цену ускорения через recall@k.

## 4. Условия проведения

- **Форма:** самостоятельная работа (дополнительное практическое задание), выполняется в часы СР по завершении раздела 4 «Алгоритмы поиска и хеш-таблицы».
- **Срок:** объявляется преподавателем при выдаче задания.
- **Трудоёмкость:** ~6 часов СР.
- **ПО:** Python 3.10+; см. [`resources/software/`](../resources/software/README.md). Векторные операции допустимы на numpy; логика поиска и хеш-таблица — собственные.
- **Вариантность:** seed генератора данных — `30 + номер варианта` (см. [`docs/reproducibility.md`](../docs/reproducibility.md)).

## 6. Задание

1. Сгенерировать данные своего варианта (`--only embeddings`) и изучить их структуру: наборы векторов резюме и вакансий, файл эталонных соответствий «резюме → релевантные вакансии».
2. **Точный поиск.** Для каждого резюме найти k ближайших вакансий линейным сканом по косинусной близости. Векторные операции (скалярное произведение, нормы) можно выполнять на numpy; логика поиска — собственная. Корректность подтвердить на эталонных соответствиях и репрезентативных тестах (в т. ч. граничных: база из одного вектора, k больше размера базы).
3. **Ускорение (LSH).** Реализовать бакетизацию случайными гиперплоскостями: подпись вектора из m бит (знаки скалярных произведений с m случайными гиперплоскостями); кандидаты для запроса — векторы из бакета его подписи; точный поиск выполняется только по кандидатам. Бакеты хранить в **собственной** хеш-таблице с цепочечным хешированием (по образцу ЛР 8); готовые ассоциативные контейнеры для хранения бакетов не использовать (допустимы только как эталон в проверках).
4. **Сравнение.** Для не менее чем трёх значений m (например, 4 / 8 / 16) измерить по методике бенчмаркинга (прогрев, ≥5 повторов, медиана) время запроса точного и приближённого поиска и вычислить recall@k приближённого поиска относительно точного; результаты свести в таблицу или график «время — полнота».
5. **Отчёт.** Вывести аналитически сложность обоих подходов (линейный скан и LSH: построение индекса и запрос), описать наблюдаемый компромисс «скорость — полнота» и сформулировать вывод о применимости каждого подхода.
6. **Обзор.** Добавить в отчёт обзорный абзац: как задача поиска ближайших соседей решается на промышленных объёмах (инвертированные индексы, графовые методы типа HNSW) — без реализации.

## 7. Формат сдачи

- Код (точный поиск, LSH-бакетизация на собственной хеш-таблице, эксперимент) и краткий отчёт (таблица/график «время — recall@k», асимптотика, выводы, обзорный абзац) в личном репозитории обучающегося.
- **Защита:** демонстрация эксперимента на данных своего варианта + ответы на вопросы (см. раздел 10).

## 9. Правила использования внешних ресурсов и генеративного ИИ

- **Разрешено:** документация Python и numpy, справочники; генеративный ИИ — для пояснений материала (в т. ч. свойств LSH), отладки собственного кода и генерации дополнительных тестовых данных.
- **Обязательно:** любой использованный ИИ-код верифицируется по методике [`docs/ai-verification.md`](../docs/ai-verification.md) (инварианты, репрезентативные тесты, сравнение с эталоном — для приближённого поиска эталоном служит собственный точный линейный скан, — оценка сложности); результаты верификации включаются в отчёт.
- **Анти-чит:** готовые библиотеки поиска ближайших соседей (faiss, annoy, sklearn.neighbors и т. п.) в основной части запрещены; замеры и recall@k вычисляются на данных своего варианта; выводы формулируются по собственным результатам. Непонимание собственного решения на защите = 0 баллов по критериям «полнота верификации» и «обоснованность выводов».

## 10. Вопросы для защиты

1. Какова сложность линейного скана по базе из N векторов размерности d для одного запроса и как она проявилась в замерах?
2. Что такое recall@k и как он вычислялся в вашем эксперименте?
3. Почему бакетизация случайными гиперплоскостями приближает именно косинусную близость: как связаны вероятность совпадения битов подписи и угол между векторами?
4. Как выбор числа гиперплоскостей m влияет на размер бакетов, время запроса и полноту поиска и где на вашем графике «время — recall@k» разумный компромисс?
